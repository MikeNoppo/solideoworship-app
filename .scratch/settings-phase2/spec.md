# Settings phase 2: labels and transitions

Status: implementation authorized by the user's phase-2 choice and confirmed shortcut/cycling/transition preferences. V1 remains the foundation at d4173cd. No further approval is required for routine implementation choices below.

## Outcome and selected behavior

Add two Settings categories, Song Labels and Transitions, using the existing EN/ID design and draft/Apply/OK/Cancel/reset behavior. Preferences remain global, stored atomically with existing Settings, compatible with v1 databases and schedule files. Source lyrics and projected section heading colors are unchanged by operator label styling.

Labels: configurable name, aliases, background color, optional one-letter A-Z shortcut; add/delete/reset entries. Up to 32 entries, names/aliases up to 64 characters, up to 8 aliases per entry. Show a readable label chip in operator slide thumbnails and live rows while preserving current/live selection accents. No chips on the projector. Unknown/unlabeled sections retain neutral styling. Defaults: Verse (aliases Verse/Bait, V, blue), Chorus (Chorus/Reff/Refrain/Korus, C, purple), Pre-Chorus (Pre-Chorus/Pre Chorus/Pra-Reff, R, rose), Bridge (Bridge/Jembatan, B, green), Intro (Intro/Introduction, I, teal), Interlude (Interlude, L, blue-grey), Tag (Tag, T, orange), Ending (Ending/End/Outro/Coda, E, red). Default colors should be restrained and text readable; computed white/dark foreground based on contrast avoids another color preference.

Shortcut behavior is fixed by the user: Alt/Option + configured letter navigates the current live song, repeated presses cycle forward through distinct matching sections and wrap. Verse 1 continuation slides belong to the same section; a repeated heading later is a separate occurrence. From an unrelated section, choose the next matching section after the current slide, wrapping if needed. A single matching section returns to its first slide. Shortcut does not open output, switch schedule items, clear Black/Clear, or run on Scripture. B/C retain Black/Clear. Reject duplicate shortcut letters and overlapping normalized names/aliases; blank shortcut disables binding. Match case-insensitively, ignore whitespace/hyphen/underscore differences and trailing ASCII section numbers. Normalize for matching without allocations in view. Preserve arbitrary lyric headings in stored data.

Global section shortcuts must not fire while typing or any modal is open. Handle only Alt with no Ctrl/Cmd/Shift and no auto-repeat. For control-window input, check focused input state before executing (event Ignored alone is insufficient for Alt). An existing focused control input must not block a shortcut deliberately sent to the output window. Discard delayed focus-check results after a new live presentation or modal change. Plain shortcuts and clipboard behavior remain unchanged.

Transitions: independent slide, Black and Clear choices, each Cut or Fade, duration 100..=2000 ms in steps of 50, default Cut with remembered Fade duration 500 ms. Returning from Black/ Clear to Show uses that mode's setting; switching to another mode uses the destination mode setting. Go Live, keyboard/row navigation and section shortcuts use slide transition settings. Same-target/no-op commands do not restart animation. User input is immediate logically; never queue a navigation behind animation.

Fade means outgoing text fades out then incoming text fades in over a smoothly interpolated solid background; it is not a screenshot-based or pixel-exact cross-dissolve. For the same scene changing Show/Black/Clear, interpolate body opacity directly over the complete duration and background as appropriate. When no old text is visible, fade the new text in directly. Retain at most source and target snapshots using Arc decks and copied theme data, never clone slide bodies per frame. A new command interrupts using the currently sampled visible scene, opacity and background, then retargets continuously with bounded state. Different output layout/aspect/margins uses Cut so incompatible canvases do not jump during a Fade. Opening/closing/moving output windows is immediate; moving an output preserves logical live scene and Black/Clear as v1 does.

One shared transition progress sample drives the live preview and projector. Only subscribe to native frame events while a live transition or Settings demo is active; remove subscription and temporary snapshots when complete. Clamp progress to monotonic 0..1 and ignore older frame timestamps. No always-running timer, unconditional rendering, image decoder, screenshot readback or new dependency. Settings changes do not mutate an in-flight transition; next commands use saved settings. Operator label colors/shortcuts update after Apply immediately; projected styles keep v1 next-Go-Live behavior.

Transitions Settings includes a Preview button using existing two-section sample song material. The demo runs only inside Settings, uses the selected slide/Black/Clear transition option, never changes real Live or output, and stops on reset/cancel/close/save as appropriate. The same conditional frame message can advance the Settings demo. Explain Fade's fade-out/fade-in behavior in translated helper copy. Label category shows a usable bounded table and local chip samples; it need not keep the unrelated song-canvas preview beside the table at narrow widths.

## Shared contract and implementation boundary

Core remains iced/SQLite/serde-free. Add core labels module: `LabelRule { name: Box<str>, aliases: Vec<Box<str>>, color: Rgb, shortcut: Option<char> }`, `LabelSettings { rules: Vec<LabelRule> }`, defaults, normalization/matching, validation and rule lookup. Add `Settings.labels: LabelSettings`. Add `TransitionMode::{Cut,Fade}`, `TransitionSpec { mode, duration_ms:u16 }`, `TransitionSettings { slides, black, clear }`, and `Settings.transitions`. These types can live in a core transition module and reexport where helpful. Settings validate/clamped includes new fields; new SettingsError variants must be localized through i18n::Localize (temporary existing invalid-values copy is acceptable until UI supplies specific text).

Add generic `SlideSection { name: Box<str>, start: usize }` and `SlideDeck.sections: Vec<SlideSection>` (empty for Scripture), populated by the song compiler only for nonempty source heading blocks. A blank line/line-limit continuation does not create a new section. Add section lookup by slide index and pure matching/next-section behavior at the Presentation/LabelSettings boundary. Keep Slide itself source-agnostic, legacy compiler entrypoints usable, and schedule serialization unchanged. Adding fields requires minimal literal fixes throughout the workspace; do not discard existing tests.

Library adds new private DTO fields to the aggregate record. Missing v2 fields use new defaults without losing v1 values; malformed new sections fall back independently where possible, rather than discarding an otherwise valid v1 aggregate. Reject invalid saved rows/duplicate aliases or shortcuts. No shipped migration changes. Existing styles/shadows methods remain compatible.

App transition helper under `render::transition` owns reusable `Scene` snapshots (Presentation + SlideTheme + OutputState), sampled frames/background/opacity and timeline logic with injected Instants for tests. API signatures may be proposed by renderer worker, but must support source/target snapshots, interrupt/rebase, advance/is_active and a borrowed frame renderer usable by output, live panel and modal demo. Extend slide renderer with borrowed-stage helpers accepting body opacity and background override; avoid cloning a theme per view just to change colors. Native frame subscriptions are passive, but their App messages request redraw via iced's event loop, sustaining only the active animation. Research: /tmp/sdw-phase2-fade-research.md.

App label lookup/style caches are refreshed on source/settings/Go Live changes, or use allocation-free bounded lookup. Avoid allocating normalized label strings on redraw. Section hotkeys only navigate a live deck; App must expose a small confirmed-navigation helper so final transition integration routes the same mutations into the Fade controller. Keep existing live cursor/Arc source and v1 output lifecycle protections.
